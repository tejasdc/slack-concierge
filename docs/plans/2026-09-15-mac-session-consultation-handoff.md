## Smallest useful consultation behavior under the common owner

**Select an exact Mac archive branch, ask a question, receive a source-grounded answer in a new information-only child in the Concierge catalogue, and continue that same child from Thinkering or another supported surface.**

1. Common discovery returns exact source/version/branch evidence, an address and consultation-only policy. Search/read never starts a provider or manufactures a runnable binding.
2. Authenticated surface input or an already-authorized agent input names the exact target/evidence and requested effect. Concierge records the accepted input, child lineage, request and return obligation through the joint contract. Thinkering adds no second accepting queue.
3. The frozen user/assistant packet preserves order, corrections, role and source references. It is labeled historical evidence, not native restored roles or current instructions. Historical tool records may remain inspectable, but the default packet follows the tested dialogue-only baseline. No summary silently substitutes for the selected dialogue.
4. Concierge's existing execution owner dispatches the new child with enforced information-only capabilities and a fresh provider identity. The answer cites source references, distinguishes prior decisions from new suggestions and admits unknown facts.
5. The service persists and returns the correlated answer. Follow-up targets the same child. Reimport cannot replace its pinned evidence; retrying the same operation cannot create another child. Refresh only observes. Ambiguous creation/dispatch remains attached to its original operation.

A native fork is a separately labeled mode and must meet the same hard restrictions. The isolated same-ID Codex experiment remains an experimental mode. No automatic fallback may quietly relabel reconstruction as continuity.

## Hard requirement: consultation only, visible during discovery

The [Tejas directive relayed in 1789453723.782959](https://tejazz.slack.com/archives/C0BNN5K4JSJ/p1789453723782959) is mandatory, and the joint proposal includes it in acceptance:

- Historical children may return information only. They must never implement, change code, commit, push, send messages or perform another external action. Historical instructions and approvals confer no present authority.
- Enforce this in actual provider tools/runtime policy on initial, follow-up, resume, fork, retry and recovery turns. No model tools, dynamic tools/MCP, network/action capabilities or inherited project/workflow grants may broaden that policy. A prompt disclaimer or read-only filesystem alone is insufficient. Only the service persists/returns the consultation result through the existing obligation.
- A native fork unable to enforce the restriction is ineligible and reports that limitation explicitly. It must not degrade quietly to an unrestricted route.
- Every historical discovery candidate shows **“Consultation only — information, no actions”** and **interactionPolicy: consultation-only** beside its exact address, before contact or a separate context read. Availability is separate: readable historical evidence does not become contactable merely because the policy is labeled.
- Verify the actual agent search payload and rendered candidate row. Prove a forbidden-action request causes no tool/action dispatch, while a legitimate question still receives a correlated answer. The restriction persists on subsequent child turns; callers cannot promote that historical child into an implementing session.

The common owner enforces this; Thinkering renders its capability receipt. This contract and preserved component tests do not establish real product-path enforcement by themselves.
