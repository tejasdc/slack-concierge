# Antigravity on the Google AI Pro subscription

## Requirement and observed facts

Tejas asked to use his Google subscription for agents, show its remaining capacity beside the existing provider accounts, let eligible saved and automatic work use it, and compare it on real earlier tasks before assigning it a role.

The subscription owner is `tejastej.dc@gmail.com`: a Google Play renewal notice dated 2026-10-11 names Google AI Pro (5 TB), renewing 2026-11-11. The server has Antigravity CLI 1.3.3 installed. The personal Google integration in Thinkering is a mail/calendar connection; it is not Antigravity authentication.

Correction, 2026-10-12: the older Gemini CLI authentication and quota pages are obsolete for consumer subscriptions. Google's current [deprecation notice](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals) says individual, Google AI Pro and Ultra accounts lost Gemini CLI sign-in on 2026-06-18. A live request after successful Google sign-in failed with `UNSUPPORTED_CLIENT`. The old 1,500 requests/day figure must not be represented as available capacity. Google directs subscribers to Antigravity CLI. Its [installation and authentication guide](https://antigravity.google/docs/cli/install/) supports Google OAuth over SSH, and its [headless mode](https://antigravity.google/docs/cli/headless/) supports cached sign-in, JSON results, resumption and a streaming input protocol. Its [quota command](https://antigravity.google/docs/cli/commands/usage/) displays live remaining allowance and refresh timing. The [changelog](https://antigravity.google/docs/changelog?tab=cli) confirms that `agy -p "/usage" --output-format json` returns a structured quota snapshot without spending model allowance. Its [pricing](https://antigravity.google/pricing) describes Google AI Pro as higher limits and an AI credit pool, without a fixed daily count.

The current Codex custom provider speaks the Responses API, while Google's published OpenAI compatibility uses Chat Completions. Subscription OAuth cannot be used for a direct Codex custom provider, so this delivery does not configure Codex to impersonate Antigravity CLI.

## Ownership and invariant

Concierge's canonical owner retains the session, accepted input, model selection, scheduled/banked status, usage snapshot and exact execution receipt. Antigravity CLI owns its Google credential, model conversation, filesystem tools and its own session history on the server. Thinkering displays the owner's provider account and capacity projection; it does not authenticate with Google independently. The Mac reaches this provider through the existing peer and request path; the subscription credential stays on the server.

An accepted turn may be sent to Antigravity once. Before the CLI sees it, the owner records the exact input and a durable execution identity. After a coordinator restart, it resumes or inspects the same CLI execution; if delivery cannot be proved, the owner marks the outcome unconfirmed and never repeats that input. A follow-up keeps the same Antigravity conversation UUID. Stop cancels the active prompt. An Antigravity refusal belongs to Google, never to Claude or Codex.

Capacity has one authoritative source: Antigravity's own reported quota snapshot. Google says the plan's five-hour and weekly quotas are work-weighted, so there is no fixed request count to claim. If the CLI cannot give a fresh, parseable model-specific allowance reading and reset, the dashboard says capacity is unverified, and automatic choice and bank release cannot treat that provider as having room. An explicit Google request can still try and report its actual outcome. No count reconstructed from Concierge's own jobs may masquerade as Google's account-wide balance because other Antigravity surfaces share the allowance. The CLI defaults to no automatic AI-credit overages, and Concierge refuses dispatch if they are explicitly enabled; using the subscription's included allowance never silently becomes a purchase.

Antigravity's current quota response has separate Gemini and third-party model groups; this integration reads the Gemini five-hour and weekly buckets for the `google` alias. The quota reply does not establish which Google login produced it, so the CLI's documented status-line payload records only email and plan in a root-only file. Deployment installs that command from the sealed release into a durable local hook slot, which remains available if the release rolls back, while preserving other CLI settings. The reader also checks `agy models` before `/usage`, because a live unauthenticated `/usage` opened an OAuth prompt despite closed stdin. The dispatch entrance refuses an explicit `useG1Credits` on setting. No peer quota can authorize this server's Google credential.

## Acceptance and comparison

The implementation is one complete delivery: server Antigravity process and recovery, one owner selection and usage path, Thinkering account and model surfaces, saved-work handling, install/update ownership, and project documentation. The installed check sends one marked native request through Concierge, verifies its accepted input, reply and Google session continuity, then confirms Thinkering's account reading and a saved-work dispatch. No replay experiment uses production state.

The comparison uses real prior bugs at their pre-fix commits in isolated worktrees. Gemini and the original agent model receive the same task, repository state, tool access, time limit and test budget, with no production deployment authority. Score diagnosis against retained traces, exact patch behavior and regression gate, reliability (tool errors, stuck runs, incomplete work), elapsed time and model requests. The Oct 10 typing/deletion jank release still had a 140 ms copied-data insertion and missing native Mac Safari acceptance, so it is not scored as a full success. The Oct 10 writing-pad keyboard replay was inconclusive because Chromium could not launch in this server environment; it cannot justify routing. A command-level replay of the Oct 8 silent dispatch hang is being prepared instead. Only measured performance may change the model-selection rules.

The dispatch replay also exposed a provider-contract risk: the CLI can label a bounded run `SUCCESS` while supplying no final reply after an edit. Concierge now treats a successful empty reply as **unconfirmed**, preserving the accepted input without declaring the work done or replaying it. Its production invocation uses no print timeout, but the empty-result refusal is still necessary for any future occurrence.

Automatic new-session choice remains Claude/Codex. An explicit Google session and explicitly Google-bound saved work can use the included Gemini quota once the integrated route is installed and checked live. Existing sessions retain their provider. The two replays do not justify moving nightly reviews, banked work, bug fixes or the default model to Gemini. A later comparison on representative recurring reviews would be needed before adding that placement to model-selection rules.
