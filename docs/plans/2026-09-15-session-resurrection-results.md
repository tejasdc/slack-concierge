# Historical consultation: executable results

Completed bounded experiment, **2026-09-15 UTC**. This follows the [design brief](https://github.com/tejasdc/slack-concierge/blob/8904e116c2a9431461a9653850b767090954ce6b/docs/plans/2026-09-14-historical-session-consultation.md). Tejas authorized actual calls and prioritized useful recall of user/assistant context over exact tool-state fidelity; the subsequently delivered ChatGPT export is included. Communication implementation remains independent.

## Findings

**Useful historical follow-up works for all three tested formats. A labeled text packet was as effective as role-preserving reconstruction on these small fixtures. Native continuity worked in two distinct ways, with an important Codex fork failure.**

| Selected source | Native subject | Pi AI structured messages | Cited-text baseline | No-history control |
| --- | --- | --- | --- | --- |
| C1: Mac Claude Code; 4 user + 12 assistant messages | A native child answered using `claude-sonnet-5`; 3/6 common facts | 5.5/6 | 5.5/6 | 0/6 |
| X1: Mac Codex; 6 user + 38 assistant messages | An isolated copied-profile resume answered using `gpt-6-astra`; 4.5/6. Native fork failed. | 5.5/6 | 5.5/6 | 0/6 |
| G1: actual ChatGPT export; 6 user + 6 assistant messages | No ChatGPT-native resume attempted | 6/6 | 6/6 | 0/6 |

These are **exploratory retention scores**, not model rankings or reliability percentages. Six source-quoted facts were frozen per case before subject calls: actual user-role requirements and prior assistant decisions, including corrections. Each received 0, 0.5 or 1 for absent, partial or qualified retention. Astra graded anonymized answers; all credited answer quotes were checked. Native answers were then audited against their actual tool-inclusive history. Claude's native subject used a different model; the native contexts were much larger. One sample per source format, leading aspects of the questions, and same-family fixture author/scorer limit inference. There were no repeated trials. Scores are not a release gate.

All nine Pi comparison calls and both successful native calls correctly treated the deliberately unestablished facts as unknown. The no-history controls could give general advice but did not recover specific historical decisions. Both reconstruction modes gave actionable revisions tied to the historical constraints. They missed one small qualification in C1 and part of a verification restriction in X1. An additional G1 follow-up completed after appending the first answer and a new question to the serialized structured context; it was not included in the six-fact comparison.

The native answers recovered useful history and extra facts from old tool results. They also omitted some original requirements. The Claude child misattributed an assistant decision as a user mandate, altered historical quotations, and asserted a background-worker failure unsupported by the archive. The Codex continuation was mostly grounded; it omitted part of the original review scope and blurred a later verification restriction with an earlier check. More persisted material did not automatically yield better requirement recall in these examples.

## What actually ran

- **Pi AI 0.85.1**, locally pinned with a lockfile. All reconstruction, baseline, control, fixture-author and scorer calls explicitly requested **`gpt-6-astra`** through the OpenAI Codex API. Captured request shapes prove separate user/assistant roles for structured mode, one user message for the baseline, and zero tools. Pi's reported model is SDK metadata initialized from the explicit request; it is not an independently observed backend model identity. No model alias or fallback was used.
- **Claude Code 2.1.263**, reading a private copy of a Mac **2.1.224** archive. `--resume <exact-id> --fork-session --resume-session-at <exact-leaf>` produced a different native session ID. Initialization exposed `tools: []` and `mcp_servers: []`; assistant events and native usage reported **`claude-sonnet-5`**. The original profile copy and archive hash stayed unchanged.
- **Codex CLI 0.153.4**, in a separate stdio App Server process and isolated profile, reading a Mac **0.136.0** rollout. The successful `thread/resume` retained the original native ID in that private profile; the new native `turn_context` reported **`gpt-6-astra`**, `/work`, read-only sandbox and no approvals. It changed only the disposable profile copy. Both native subjects recorded zero new tool execution.
- **ChatGPT export dated 2025-11-21**, selected by exact conversation ID and `current_node`. The retained branch had twelve visible text messages and a source model label of `gpt-5-thinking`. The live answering model was Astra. This was a new reconstruction, not a ChatGPT session transfer.

All raw sources, questions, exact quotes, responses, native profiles and logs remain under the owner-private `/root/.local/share/session-resurrection-experiments/`. The committed [evidence JSON](2026-09-15-session-resurrection-evidence.json) contains aliases, hashes, counts, modes, model evidence and scores; it contains no dialogue. Runnable code and commands are in [experiments/session-resurrection](../../experiments/session-resurrection/README.md).

## Native failure and adoption findings

1. **A provider “success” label can conceal failure.** The first Claude subject requested `claude-fable-5-1`. It returned a usage-credit error with `subtype: success`, `is_error: true`, a synthetic assistant model and empty model usage. It produced no consultation. The separately named Sonnet attempt succeeded. The runner now rejects that contradictory success envelope.
2. **An unregistered Codex file path was insufficient in this run.** A `thread/fork` path attempt returned “no rollout found.” Preserving the native dated filename/layout in the private profile made ID-based discovery work. A cold `thread/read` returned no turns; the subsequent native fork hydrated four. Empty UI/catalogue history and inability to resume are different claims.
3. **The native Codex fork failed at the model boundary.** Forking created a child ID, but the first turn failed with HTTP 400 `invalid_encrypted_content`: the encrypted item's ID did not match the target item ID. The archive and child were not rewritten to suppress the error. A separate copied-profile resume using the same original ID succeeded. This isolates an observed old-archive/new-fork compatibility failure; it does not establish that all Codex forks fail or prove the upstream root cause.
4. **Native ID reuse needs an isolated namespace.** The successful copied-profile continuation is evidence of provider continuity for this source, not permission to bind that same native ID to two active owners in Concierge. Keep native profile/host namespace and logical consultation-child identity distinct. Do not introduce automatic fallback that silently relabels reconstruction as continuity.
5. **The reviewer must see the evidence the subject saw.** A first dialogue-only grader incorrectly called some native tool-derived details unsupported. Re-auditing against the full selected native history corrected that mistake and increased X1's score from 3 to 4.5. Native tool records supported historical code changes, tests and review artifacts; they did not establish current deployment or user approval. The initial grader also treated one no-history abstention as missing supplied evidence; that judgment is excluded from conclusions. Automated grades need an evidence-boundary audit.

OpenClaw's gateway/catalogue adoption was **not executed**. The earlier source investigation found that its Claude and Codex adapters use these native resume/fork primitives plus a lossy display mirror. These experiments validate underlying native paths only; they are not an end-to-end OpenClaw adoption test. Its binding/provenance patterns remain reusable, but adopting its gateway would not by itself prove compatibility with the failing encrypted-history fork. [Pinned OpenClaw Claude adoption source](https://github.com/openclaw/openclaw/blob/df9b55315051b17914c29c0d20ac4ae23859e519/extensions/anthropic/session-catalog-continue.ts), [Codex adoption source](https://github.com/openclaw/openclaw/blob/df9b55315051b17914c29c0d20ac4ae23859e519/extensions/codex/src/session-catalog-adoption.ts).

## ChatGPT: retained context and omitted state

The machine-readable corpus contains **504 conversations, 9,412 nodes and 43 branch points**. `chat.html` was not indexed as another source. The selected experiment followed one exact parent chain; sibling branches did not enter its prompt. Synthetic branch/cycle tests cover selection behavior; the selected live case itself had no branch point.

The export also contains 449 multimodal messages, 259 image pointer blocks, 310 embedded audio transcriptions, and 190 attachment metadata references. Metadata key spelling varies (`mime_type`/`mimeType`, `size`/`fileSizeTokens`, etc.). A simple attachment-ID filename-prefix scan found possible local candidates for 79 of 190 references and exact original-name matches for none. **These are association candidates, not validated asset resolution or 111 proven missing files.** Some references repeat, and generated assets use different layouts. No attachment bytes were given to these subjects.

There are 246 `user_editable_context` blocks carrying `user_profile` and `user_instructions`, plus contextual/system metadata. `user.json` contains account/profile fields; it is not evidence of a complete saved-memory store. The experiment omitted those context blocks and all hidden/system material. Available historical profile text could later be supplied as explicitly labeled evidence; it must not silently become current system authority. Whether the export fully captures saved memories, project/GPT instructions, retrieval state or personalization remains unproven.

The decoder retains ordinary visible dialogue and already-exported `audio_transcription.text` within multimodal messages. It counts excluded media and attachment references. Embedded audio handling is schema-observed and fixture-tested; G1's semantic experiment was text-only. It did **not** reproduce original audio/video, image understanding, image-generation state, canvas state, tools, product memory retrieval or citations' external content. Pi supports explicitly supplied image bytes, but this run did not resolve and test private export assets. Existing bytes are potentially usable inputs, not inherently lost state; an opaque pointer alone is not a usable attachment. [Pi context/image API](https://github.com/earendil-works/pi/tree/main/packages/ai), [OpenAI export documentation](https://help.openai.com/en/articles/7260999-how-do-i-export-my-chatgpt-history-and-data).

## Supported modes and practical recommendation

| Mode | Evidence-backed status for this experiment |
| --- | --- |
| `reconstructed_role_text` | Useful on selected Claude, Codex and real ChatGPT histories; repeatable with saved role-bearing context. |
| `cited_context` | Equally effective on these six-fact comparisons; simplest useful baseline for a bounded consultation. |
| `native_child` / Claude | Successful for the selected archive and Sonnet subject, with enforced no-tool policy. |
| `native_child` / Codex | Failed for the selected old archive on 0.153.4; retain explicit failure until compatibility is proven. |
| `native_isolated_copy_resume` / Codex | Successful in a private namespace while retaining the native ID; not tested as a shared-service adoption path. |
| Full OpenClaw adoption, Pi coding-agent sessions, multimodal reconstruction, complete ChatGPT product-memory restoration | Not tested or claimed supported. |

For the current usefulness criterion, **a selected user/assistant evidence packet is already sufficient to offer meaningful consultation**. Role-preserving storage earns its place by retaining explicit authorship/order and making further turns easy, not by a demonstrated answer-quality advantage here. Pi AI supplies that small seam without another coding-agent runtime. Keep a common provenance wrapper so either mode can sit behind Thinkering's session interface and Concierge's existing execution owner. No integration was implemented.

Retain: source provider/profile namespace, source ID, byte hash/revision, selected leaf/cutoff, retained message refs and hashes, original source role versus proven author, transformation/version, omission counts, requested and actually reported model evidence, child/native ID relationship, private execution profile, permissions/tool policy, and completed/error result. X1's user-role prompts belong to a historical delegated review; this experiment does not independently establish that each was written directly by Tejas.

Before making an import contactable, require: immutable source and complete selected branch; explicit missing/context/media policy; native ID/profile compatibility where applicable; a meaningful source-quoted requirement/decision follow-up plus an unestablished-fact check; no unintended tool/goal activity; and exact preservation of the original. Read-only consultation must be enforced by runtime policy and filesystem isolation. Neither a catalogue entry, successful fork metadata, nor answer fluency is enough.

## Verification and limits

Twenty-one focused tests pass, including a real Linux `bwrap` filesystem check proving absence of live root/service paths and inability to write system paths. Python compilation and Node syntax checks pass. One fresh Astra review found three reproducible tooling defects: unconstrained grader metadata could reach public evidence, the ChatGPT archive was missing from output guards, and a refused grading regeneration could overwrite existing answer labels. All three were corrected in one pass with focused regressions; failed-start credential cleanup was also checked. The stricter exporter reproduces the committed evidence exactly, so these defects did not alter the measured results. Correction verification used tests and parent self-review, with no second review verdict.

The measured archive hashes still match all three originals. No original history was edited, no historical tool was executed, and no managed daemon was restarted or updated. This branch changes experimental tooling/docs only; there was no product integration, service restart or deployment.

Unknowns remain concrete: more archive versions, compaction/dependency prefixes, longer and conflicting branches, true attachment resolution and multimodal usefulness, preserved ChatGPT context versus full product memory, model-grader repeatability, and the upstream encrypted-fork failure mechanism. The experiments do not establish independence of historically related reviewers or present-day correctness of old code.
