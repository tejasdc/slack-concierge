# Journal observation admission

thnkr.ing's canonical server owns saved journal words and a durable queue for screen entries and check-ins. When one is ready, it calls `POST /sessions/v1/journal/observations` on Concierge's authenticated owner transport with `{clientActionId:"journal-tracker:<64 hex>",objectId:"journal-entry:<id>"|"checkin:<id>",processingVersion:1}`. The route accepts only this closed shape and addresses the existing journal keeper session. It never accepts client-supplied journal text or a destination session. An unversioned caller retains legacy tracker filing; an unsupported version is refused rather than downgraded.

Concierge records the input with **service** origin, a stable action ID and queued delivery. This is important: the ordinary thnkr.ing session input route records Tejas as author, and would misattribute a server-generated request. Retried calls with the same ID are one admitted input. The receipt proves Concierge took it, not that the keeper has filed values. The keeper reads the original source from thnkr.ing's private capability socket, records supported observations there, and reports the saved result.

This boundary keeps provenance at the system that owns each side: thnkr.ing owns note words and tracker properties; Concierge owns the keeper session and execution. It avoids another journal agent or a second tracker store. Release order is Concierge first, then thnkr.ing, because the latter begins calling this endpoint after activation.

## Processing saved reasons

Version 1 asks the same keeper to separate passive reflection, explicit requests and reasons requiring assessment. Saving a journal entry remains independent of processing. Before successful processing completion, the keeper submits the source-bound disposition described in [the Inbox processing contract](native-inbox.md#journal-processing-dispositions). It names the canonical root revision and complete source version, so adding a child command makes an older review stale even when the root stays unchanged. The canonical private reader supplies source revisions, actors, original event times and evidence; neither the caller nor the model can invent them.

An actionable portion retains its exact located quote and source reference. It creates an agent-authored Inbox request before routing, or links existing retained work with source evidence. Source identity survives reviewing runs and word versions. A lost response never authorizes replay of an admitted or uncertain effect. A request to assess friction does not grant a blanket bypass, and agent/imported words do not become human instructions. Reflections create no Inbox work thread.

The observation admission remains a delivery receipt. A structured review is evidence of classification and handoff; the receiving actor's explicit outcome is evidence of the resulting action. The new agent completion check is about that processing claim, not a new question, field or permission step for the person writing. Earlier admitted inputs are preserved rather than replayed for a newer receipt.
