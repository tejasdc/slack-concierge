The question gate accepts a device-only claim when its question names one action on a
physical device. The agent first uses its available device route. If that route reaches
a physical prerequisite such as unlocking his Mac, the question names that prerequisite.
Starting one named app on an e-reader, watch or TV can also be a physical prerequisite:
for example, KOReader must be started on a Kindle before it exposes an agent connection.
The required explanation says which route was tried and why the agent cannot do that
step itself. A generic request to open an app or website remains refused.
The ask is the question's first sentence, phrased "Can you unlock your iPhone?" or
"Please unlock your iPhone."; sentences after it may only state what the agent saw or
will do ("The device check reported it locked. I will handle the app inspection."). A
later sentence that asks him for more (addresses him, says "then", or is a question)
refuses the whole question, so app work never moves to him behind an unlock.

The Mac session owner observes Claude and Codex tool starts in the existing provider
progress stream. The server owner also observes tool calls that SSH to Tejas's Mac,
including a plain command and AppleScript from a server agent. For actions that can

`mac_surface_activity` event per action kind and turn with the agent's exact session,

The first action of each kind in a turn is reported: installs through common package
managers, launchd loads, Chrome debugging, screen capture, AppleScript and computer

not a claim that macOS granted a permission or that an installation completed.
The SSH observation recognizes the Mac peer's registered SSH address. Tool activity
outside the observed provider stream is not covered. macOS remains
the source of truth for its own permission and login-item records.
